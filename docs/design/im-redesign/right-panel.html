房间背台:分段器,不是页签

诊断:「线程 / 成员 / 看板」被实现成了 App 级工作台的**页签**(可开可关可加可滚), 但它们其实是同一件东西的三个视图 —— 这间房的背台。于是接连出现:看不到线程(页签按需才开)、 换房攒页签(按靶子开)、中文被截(要给 × 让位)、下钻后标题变长把自己挤出可视区。 换成固定三格分段器,这四个症状同时消失,而且 250px 下每格 ~80px,中文两字 + 状态点绰绰有余。 Files / Terminal / Browser 仍然是页签 —— 它们确实是"你打开的工具",只是不属于房面。

这间房还没有执行会话。

有人开工之后,这里会按人列出每一次执行。

空态 — 三格永远在;空的是内容,不是入口。

设计决策(实施照这个来)

  • 右栏两形态,由当前会话决定:房/私聊 → 这个分段器;直聊/工程面 → 既有工具页签 (Files/Terminal/Browser)。与"两棵壳"同一条分界线,右栏不再一套壳硬扛两种语义。
  • 分段器固定三格:等宽 flex: 1 1 0,无 ×、无 +、不可滚、不改标题。 这一条直接消灭了截断、压扁、累积、自己挤出可视区四个症状。
  • 状态点长在格子上:线程有在跑(绿)、看板有待你(橙)、成员有新消息(墨)。 不用数字 —— 系统只知道"有没有",编个计数出来比不显示更糟。
  • 下钻用面包屑,不动分段器:线程→某次执行、成员→某人空间页。 「在看哪一个」由内容头部说,那儿有整行宽度。
  • 私聊房没有「成员」格(一对一没有成员这回事):两格 = 线程 / 空间。
  • 数据一个字段都不新增:线程吃 kind∈{agent,work} + collab.roomSessionId; 成员吃 buildRoomMemberEntries + findAgentDoingTask;看板吃 CollabTask。
  • 最窄 250px 是硬指标:三格各 ~80px。行内只有副文允许省略号,头像与时间 flex: 0 0 auto,名字永不被挤没。
