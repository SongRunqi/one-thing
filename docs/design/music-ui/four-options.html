音乐交互 · 四案

同一时刻的四种表达:正在放《可惜没如果 — 林俊杰》,4:01 / 4:58。
数据只用 ncm-cli state 真给得出的字段:status / title / position / duration / progress。
注意:state 没有 paused 状态(暂停报成 stopped);歌词要加密 ID,而 title 只是显示串 —— 所以只有播控走类型化工具时,甲案的歌词才成立。

甲 幽灵 · 音乐住在 placeholder 里

主张:音乐不该有 UI。 零新增 DOM、零像素。唯一痕迹是 composer 上沿那个本来就存在的 frame tag,以及你不打字时 placeholder 里飘过的一句歌词。 你一动键盘它就消失 —— 它从不与你争夺那块地方。复用 composerPlaceholder 已有的多路复用(Listening… / Transcribing… / Ask anything…),歌词只是第四路。

CHAT
NOW PLAYING ♪ 如果我 还爱你,只是不想告诉你

代价:没有进度、没有控件、不能点。想暂停只能跟它说"暂停一下"。
陷阱:优先级必须是 voice > 歌词 > 默认;有草稿时让位。这是氛围,绝不能盖住功能提示。

乙 账页 · hover 才浮出的一行控制台

主张:音乐是一个后台任务,和 Goal、BackgroundJobs 是同类。 所以它长得跟它们一样,住在同一个位置(.composer-anchor 的 flyout,绝对定位,不占布局),遵守同一套画线风。 鼠标靠近 composer 上沿才浮出;移开就收。信息完整、可点、可 Tab。

CHAT
NOW PLAYING ▸可惜没如果 — 林俊杰 4:01 / 4:58 内置 ▾
COMPOSER Ask anything...

代价:hover 才有 = 不 hover 就不知道在放什么。要给键盘用户一条路(frame tag 可 focus)。
陷阱:.command-feedback 也是 bottom:100% 的浮层,两者会打架 —— 规则是它优先,音乐栏此时不展开。
暂停键必须调 pause 而不是 stop:stop 会拆掉播放会话,下次起播要重新冷启动(那一步不稳)。

丙 在对话里 · 音乐是对话的产物,不是应用的边栏

主张:根本不要状态栏。 是 DJ 给你放的歌,那它就该出现在 DJ 说话的地方 —— 消息流里,像工具调用一样。 串词、曲目、热评在一张卡里,进度就地推进。往上滚,就是今晚的歌单史。

可惜没如果 林俊杰 · 新地球 4:01 / 4:58
热评 · 如果当时我勇敢一点,结局是不是不一样。
COMPOSER Ask anything...

代价:滚上去就看不见了 —— 它没有"当下"这个概念。切歌要嘴说。
但它独有一样别人没有的东西:热评(comment list-hot)。那是网易云的灵魂,也是这个产品唯一别人做不出来的素材。
陷阱:卡里的进度要活,意味着历史消息也在轮询;必须只有"当前那张"活着。

丁 氛围 · 一条会呼吸的线,一个字都没有

主张:你已经知道在放什么 —— 你在听。 屏幕不需要再告诉你一遍。 窗口底沿一条墨线随进度推进,换歌时呼吸一次。零信息、零控件、零文字,只有"它还在"这一件事。

WINDOW
( 整个应用 · 音乐只在底沿那条线里 )

代价:不知道是什么歌、不知道还剩多久、不能操作。它只回答一个问题:还在放吗。
诚实的好处:它是四案里唯一不需要曲目身份的 —— 只用 status + position。
换句话说,只有它在 orpheus 模式下也能活(那边没有 state… 也就是说连它都活不了)。这条恰好把"orpheus 到底还要不要"这个问题逼到台面上。

甲 幽灵placeholder0 px否(只能说话)要(歌词) 赌"音乐不需要被看见"。最克制,也最容易被当成不存在。
乙 账页composer 上沿 flyout0 px(hover 时浮出)是不要 赌"音乐是后台任务"。最稳、最一致,也最没有惊喜。
丙 对话里消息流占(一张卡)否不要 赌"音乐是 DJ 的作品"。唯一能用上热评的。滚走就没了。
丁 氛围窗口边沿1 px否不要 赌"你在听,不用看"。最极端,信息量几乎为零。

甲和乙不冲突 —— 甲是收起态,乙是 hover 展开态,合起来正是 music-status-bar.md 里那套。真正互斥的是丙(音乐属于对话)和甲乙(音乐属于应用)。
丁更像是一个态度测试:如果它就够了,那前三个都是过度设计。
