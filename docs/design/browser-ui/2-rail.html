案二左轨 Rail
标签竖排成轨，顶部只剩一条地址线；轨底常驻 profile 切换。

横向标签条在窄面板里是最差的形状：每个标签只剩 60px，标题全被截成「cast…」。 本案把标签转 90°——38px 竖轨，只放 favicon，纵向可堆十几个而不挤；需要看标题时把轨拉宽到 164px（推挤视口，不浮层）。 顶部只留一条 30px 的地址线：无框，一条下划线，聚焦时线变朱砂。 轨底常驻 profile 头像——多身份隔离登录是这个浏览器区别于系统浏览器的核心能力，不该埋进设置里。 取向：同时开着多个标签、多个登录身份的人。

为什么这样

  • 竖轨的容量随面板高度增长，而面板天生高窄——形状和内容对上了。10 个标签在横条里必崩，在竖轨里刚好。
  • chrome 只剩 30px 一行，且轨与视口并排，垂直方向的损失比案一还小。
  • profile 从设置页浮到常驻位：切身份 = 换轨底头像，配合 persist:browser-<id> 的 session 隔离，语义直白。

落地要点

  • 轨宽变化（38↔164）要同步 setBrowserBounds；悬停展开建议给 120ms 延迟，否则鼠标扫过就抖一下视口。
  • 休眠态需要真的做标签冻结（WebContentsView 的 destroy + 保留 url/title 以便复活），否则淡色 favicon 是假信号。
  • "后台有新内容"点：监听非活动标签的 page-title-updated / did-finish-load。

代价

  • 横向再吃 38px。面板本来就窄，页面排版可能从两栏掉到单栏。
  • 只有 favicon 时同站多标签（三个 github 页）无法区分，必须靠展开轨或 tooltip。
  • 与右侧工作台自己的 tab 头并置，会出现"两套标签"的视觉，需要在层级上明确区分（轨是纸面色、工作台 tab 是 tab-bar 色）。
