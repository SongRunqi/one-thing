权限同意框 · 对齐 composer 的四案

现行权限框是 12px 圆角、warning 实底、带 shadow-md 的浮起卡片,右侧五颗彩色药丸按钮 —— 与 InputBox 的蓝图语言(4px 直角、零填充、hairline 分格、mono 11.5/600 裸文字、hover 才整格上色)完全是两套。 四案统一改用 composer 的骨架,差别在结构隐喻而非配色。

案一续行 · Continuation Row高度 34px · 与 composer 同框

权限不是弹出物,是 composer 顶上长出来的一格。共用一个外框(上格去底边、composer 去上圆角),读起来是同一张纸的上半截。动作沿用工具栏的 hairline 分格,和右下角 SEND 完全同构。

案一 · 续行
perm:write packages/core/engine/history.ts +2 queued
继续说点什么…
opus-4.8 think:high guard:normal ctx ▮▮▮▮▯▯▯▯▯▯ 37%
SEND
强视觉上零新增物件,权限只是 composer 多了一行;四个动作平铺,一次点击到底。
弱横向吃宽,窄栏时 WORKSPACE/REJECT 会被挤;"拒绝并给指令"要另开一行。

案二账页栏位 · Ledger Rows键值表 · 范围是一栏而非按钮

把请求拆成带标签的栏位(TOOL / TARGET / DIFF / SCOPE),mono 键在左列、值在右列,格线分隔。授权范围不再是三颗按钮,而是 SCOPE 这一栏里的分段选择;最后一行只剩"批准/驳回"两个出口。像签一张表,而不是点一个弹窗。

SEND
强信息密度最高,能塞下 diff 摘要/命令全文;范围与批准解耦,不会误点成"永久放行"。
弱纵向最高(约 5 行),遮挡对话;两步操作(选范围 → 批准)比一键慢。

案三命令行 · Prompt Line单行 34px · 靠字母键不靠按钮

整个请求压成一行终端提示符,动作是带下划线的助记字母而非按钮 —— 与 composer 里 guard: think: 那些 mono 标注是同一种字。细节收在 ▸ 里,默认不展开。四案里最不打扰的一个。

+18 −4 · 重建历史按 turnIndex 忠实拆分 queued: bash(bun run test) · read(runner.ts)
继续说点什么…

强占位最小,和工具栏一样高;键盘助记直接暴露在界面上,重复审批极快。
弱最不显眼 —— 危险操作(rm、迁移)容易被顺手 a 掉;长路径必被截断。

案四闸门 · Gate Bar征用输入区 · SEND 位变 ALLOW

不新增容器,而是把 composer 本身切到"待批"态:外框转 warning,输入区被斜纹封住,请求内容就写在被封的输入区里,动作接管右下角原本 SEND 的那一格。语义直白 —— 你决定之前不能打字。

SEND
强零新增容器,布局不跳动;"输入被锁"这件事本身就是最强的提示,最难被忽略。
弱真的挡住了输入 —— 想边审批边打草稿就不行;scope 藏进下拉,多一次点击。
