起始页新标签打开什么 — 四方案

现状：新标签直接打开所选引擎的首页（service.ts:96 的 homeUrl）——于是每开一个标签就是一次谷歌加载，还得等网络。 改成：tab.url 为空时不挂 WebContentsView，起始页是 renderer 的 DOM（本地、零延迟、吃我们的 token、明暗自动跟随）。 四案的分歧不在皮肤，在于引擎选择摆在哪、这次选择活多久——先挑这条轴，样式再谈。

案一空线Blank Line 引擎在页内一枚字母芯片 · Tab 换，只管这一次

一张空纸，正中一条墨线。除了线和一枚引擎缩写，页面什么都没有——没有磁贴、没有历史、没有天气。 光标默认就在这条线上，开标签即打字。按 Tab（或点芯片）四枚引擎横向展开，选完线上的芯片变色，这次搜索用它；下一个新标签回到设置里的默认。

四案对照

案引擎在哪选择活多久页面有内容吗鼠标 / 键盘新增存储
一 空线页内字母芯片仅本次无键盘为主无
二 四格页面主体四格不存默认，只记「上次」只有引擎鼠标为主lastUsedEngine 一个字段
三 账页顶栏芯片持久（=设置页同一份）常去 + 最近都行固定站点 + 历史（按 profile 隔离）
四 提示符输入前缀本次覆盖 / 否则默认只有前缀表纯键盘无

四案共同的落地改动

  • service.ts:96 现在是 url ?? engine.homeUrl——改成 url ?? ''：空 URL 的标签不创建 WebContentsView，起始页纯 DOM。
  • BrowserPanel.vue 的 shouldShow 再加一条：activeTab.url === '' 时藏起原生视图（和标签列表铺开走同一条路，已有现成机制）。
  • 起始页提交仍走 store.openFromInput——URL/搜索归一那条规则只有一份，别在起始页里复制。
  • 引擎表已是单一真源（@shared/ipc 的 BROWSER_SEARCH_ENGINES），四案都只是它的不同呈现，没有第二份表。

各案的代价

  • 一：空得彻底，但「上次看的那几个站」永远要重打——重度浏览会嫌。
  • 二：每次都要做一次选择，高频搜同一家的人会觉得多一步（⏎ 走「上次」是给这个的补偿）。
  • 三：要引入历史记录——按 profile 隔离、要能清空，否则多 profile 隔离登录那套白做了。工作量最大的一案。
  • 四：前缀要背；不带前缀时不知道默认是谁——靠前缀表上那枚「默认」角标兜。

建议

  • 先定选择活多久：想要「大部分时候一家、偶尔换一家」→ 案一或案四；想要「每次都清醒地选」→ 案二；想让起始页顺带当入口 → 案三。
  • 一/四 可叠加：空线加上前缀解析并不冲突（芯片跟着前缀走）。二/三 互斥于版面。
  • 三的「常去/最近」也可以晚一步再加——先落一/二/四任一，起始页的壳是同一个组件。
