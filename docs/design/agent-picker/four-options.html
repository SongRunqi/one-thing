Agent 选择器 · 合于命令面板

现有下拉是另一套语汇:实心卡片、点线行分隔、圈点记号、双行文本。命令面板 (ComposerExtensionPanel.vue) 的语汇是:缺口框标签 + 零填充细线框 + 单行行式 [mono 名 @152px] [描述] [meta] [⏎],全篇只画两根线,强调只靠底色与墨重。 下面四案都说这套语汇,但结构截然不同。深浅色请切系统主题看。

案 A

直译 — 命令面板原样搬到 header 下

一模一样的壳:框标签写 AGENT,行是单行,agent 名走 mono 落在 152px tab stop, system prompt 首句当描述跟在同一行,右侧 meta 放 DEFAULT,选中行才出 ⏎。 当前生效的 agent 用一个朱砂小方顶在名字前——占位不占宽。

代价:system prompt 被压成一行截断,读不到全貌。好处:与命令面板/文件/技能选择器 像素级同构,零新概念,改动最小(直接复用 ComposerExtensionPanel + row 类)。

案 B

可检索 — 借 subheader 槽,开即可打字

同一个壳,但用上命令面板留的 subheader 槽(模型选择器已经在用):顶部一行 › 提示符 + 裸输入框,打字即过滤,命中字符加墨加重(与命令面板的 .command-hit 同一条规则)。行式与案 A 相同。

代价:多一次交互层级——开了要么打字要么按方向键;agent 只有三五个时是浪费。 好处:agent 一多(十个以上)就是唯一还能用的方案,且键盘流与命令面板完全一致(⌘K 肌肉记忆直接迁移)。

案 C

双栏 — 左目录,右提示词全文

壳不变,内部分两栏:左侧窄列只放 mono 名(单行、无描述),右侧一根 hairline 隔开, 随高亮实时显示这个 agent 的 system prompt 全文,底部渐隐。选 agent 这件事的真实决策依据 是提示词,而不是名字——这案把决策依据摆上台面。

代价:面板宽 560px,是四案里最重的一块浮层;窄窗口要降级回单栏。 好处:唯一能在切换前读到提示词的方案,不用跳去 Agents 设置页确认「这个 agent 到底干嘛的」。

案 D

贴条 — 不做浮层,在 tab 栏下方展开一行

取命令面板的字体与墨色,但拒绝它的盒子:点 chip 后不弹浮层,而是在 tab 栏正下方推开一条 34px 的横贴条,所有 agent 以 mono 排成一行、· 分隔,当前项加朱砂底线—— 和 tab 页签「选中加底线」是同一句话。再点一次收起。

代价:放不下描述,agent 多了会横向溢出(要滚动或折叠);且会把聊天内容整体下推。 好处:四案里最轻,没有遮挡、没有阴影、没有第二个平面;agent 切换从「打开一个菜单」 降级成「拨一下开关」,它本来就该是这个分量。
