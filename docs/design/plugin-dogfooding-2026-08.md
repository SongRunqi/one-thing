# 插件系统第二性原理:自举(dogfooding)

2026-08-11 定稿。起因:壁纸战役(2026-08-10~11)暴露的结构性不安,用户原话:
"我想要做的不是这样的形态 —— 一个插件,功能实现不了,去填补插件系统。"
本文回答这句话:那个循环的根源是什么、为什么它不是插件系统设计错了、
以及用什么建造纪律让它在结构上消亡。

上位文档:插件宪法(redesign §4.2:枚举能力、宿主执行、永不开放通用注入)
**不变**;本文是宪法之下的**建造纪律**,约束的是"能力从哪里长出来"。

## 1. 病理:被讨厌的循环

> 插件想做 X → 系统不支撑 X → 系统大兴土木 → 插件变成薄壳。

循环里插件像个借口:真正的工程全在宿主侧,插件的"意义"只剩触发施工。
壁纸是全程标本:背景能力(G 期)开门时宿主 UI 并没有准备好承接"全局视觉
行为"——109 条自绘 hover、浮面散在消费者手里、区域面各画各的。于是第一个
认真的背景插件装上后,宿主追补了六级体系、四波收敛、G7 三刀、G8 三段。

**诊断:根源不是插件系统,而是一个断层 —— 宿主自身不是用"插件能用的那套
材料"建造的。** 宿主 UI 是历史堆积的手工造物,插件 API 是旁边新开的门,
两者材质不同。插件每想做一件宿主自己没做过的事,就撞进无人区。

## 2. 原理:自举

工业解法只有一个方向(Emacs / Eclipse 是极端形态):**系统自身用插件那套
材料建造**。在这种架构里,"插件想做而系统做不到"这个类别在结构上不存在 ——
系统做任何事走的路,就是插件能走的路;系统给自己造能力时,插件 API 是
**副产品**,不是事后补的门。

onething 不需要(也不该)推倒重来成 Eclipse。需要的是**棘轮式逼近**:
三条建造纪律,让"系统能做的"与"插件能做的"之间的落差单调收窄。

## 3. 三条建造纪律

### 纪律一·自举铁律(功能立项的第一问)

任何新功能立项,先问:**插件 API 做得了吗?**

- **做得了** → 以**内置插件**形态开发(先例:log-monitor、note-skills)。
  功能落地的同时,API 被真实载荷锤炼——每个内置功能都是 API 的常驻测试。
- **做不了** → 说明 API 缺一块**系统自己也需要**的东西 → 先给系统自己造
  这一块(此刻它是系统工程,名正言顺,不是"替插件亡羊补牢"),造完把功能
  以插件形态落上去。
- **系统自己根本不需要这块** → 它就是纯产品功能,**不要硬塞插件形态**。
  (壁纸的正确判法:若当初按此条走,"用户自选壁纸"作为产品设置是更便宜的
  正解;插件形态的价值在"背景"成为多住户能力位之后才兑现。)

### 纪律二·原语自带行为(UI 层的自举 = Surface v2)

宿主 UI 与插件描述树 UI 共用同一批**自带行为的原语**。行为长在组件里:
组件画底的公式是 `color-mix(自己的 ink, 自己档位的 alpha)`,alpha 缺省
100%;壁纸/主题/密度这类全局行为 = 在根上拨几个 alpha/旋钮,**没有**中央
规则本去"覆写-快照-列名"。用了原语的面不是"被规则照顾到",是**天生会**。

推论:wallpaper.css 从 600 行词典萎缩为几十行旋钮 + 开关 + 遗留例外;
ink 快照层、派生 token 列名、两条环坑戒律 —— 这些全是"行为住在组件外"的
代价,行为内置后**连同它们要防的坑一起消失**。

### 纪律三·能力开门前的自举验收

新能力门(外观类、动作类、内容类)开放给外部插件之前,宿主必须已有
**至少一个自己人**跑在同一条 API 上(内置插件或产品功能)。第一个外部
插件不再是探路者。外观类能力另加硬验收:相关表面的原语覆盖率
(`data-surface` / surface-literal 基线数字)达标才开门。

## 4. 决策树(产品 vs 插件 vs 系统)

```
新需求
 ├─ 插件 API 现在做得了?
 │   ├─ 是 → 内置插件形态开发(API 顺带受锤炼)
 │   └─ 否 → 缺的那块系统自己要不要用?
 │        ├─ 要 → 先造系统能力(名正言顺的系统工程)→ 功能以插件落上
 │        └─ 不要 → 纯产品功能,不塞插件形态
 └─ 已是多住户能力位(≥2 个真实住户)?
     └─ 是 → 维持插件形态,宿主成本按能力摊销
```

## 5. 用新透镜复盘壁纸战役

- 背景能力开门时没有过纪律三(宿主 UI 原语覆盖率≈0)→ 第一个外部住户
  变成探路者,循环启动。
- 战役真正的产出不是壁纸,是**迟早要还的 UI 债被提前清偿**:G6 token 族、
  G1-G5 组件能力、G7 章与通用规则、G8 主题层收编、11 条棘轮规则 —— 这些
  全是纪律二的前置件。债不是插件系统造的,是它照出来的。
- far-hills / ink-brand / wallpaper 三个住户共享同一舞台,第 N 个背景插件
  宿主成本为零 —— 摊销开始兑现,决策树"多住户能力位"分支成立。

## 6. 实施排期

1. **Surface v2·行为内置**(纪律二的落地,本文档的第一个实施)。
   **S / B 两级已落地(2026-08-11),C / E 两级未落地 —— 后两级是被实测挡回来的,
   不是没做完。** 六级语义与六旋钮不变,壁纸关闭时逐字节零变化。

   已落地:
   - **S 级·态**:态 token 自带 `color-mix(墨 × 旋钮)`,归档表在
     `packages/renderer/styles/state-alpha.ts`(产出层,接 `applyThemeVariables`)
     + `state-alpha.css`(静态兜底)。新态 token **只登记一处**即入册;旧结构要在
     三处各登记一次,漏一处就是一条报障(G8-b 的 rail 窟窿即此)。
   - **B 级·纱**:区域面档位原语(`styles/components.css` 四条)自带公式,
     `wallpaper.css` 里的四条通用规则删除。

   未落地,判据如实记:
   - **C 级·可读卡**没有对应原语 —— 画笔散在 `markdown.css` 的 `.md-body` 作用域
     与各表格组件里。把 88% 塞进那些画笔会让浓度变成**全局**的(今天的作用域是
     `.app-content`),浮层里的表格与对话框里的代码块会跟着透。**要收它,先给
     "内容卡"造一个原语。**
   - **E 级·磨砂**两条都挡回来了:①`backdrop-filter: blur(0px)` **不等于** `none`
     (会建层叠上下文 + 成为 fixed/absolute 后代的包含块,实测),所以"缺省 0 =
     无成本"的内置写法是错的,唯一安全形态是 `var(--ot-frost-filter, none)`;
     ②E 级规则的价值不在浮层壳自己那笔底色,而在它**覆写 token** 之后能推动声明在
     壳与 `Menu.vue` 后代上的 `--app-menu-bg` 一族 —— 只让原语画自己的底覆盖不到,
     所以枚举清单里一行也删不掉。

   ── 批 3a 补记(2026-08-11):E 级**键归位了,枚举没消亡** ─────────────────
   上面那条"一行也删不掉"仍然成立(规则体照旧覆写 token,只是把 `blur(…)` 换成了
   安全形态 `var(--ot-frost-filter, none)`),但**键**可以归位:E 级两条规则不再
   点名 `.app-popover.is-surface` / `.app-context-menu.is-surface`,改成键在**浮面
   档位章** `.is-surface` 上(唯一产出口 `components/common/popover-surface.ts`)。
   将来接进浮面档位的组件一挂章就在册 —— "用了原语就天生会"。

   **立项时的假设被实测推翻,如实记下**:原以为"UI 收敛后所有浮层壳都过统一组件",
   逐条对过 DOM 之后是 **14 条里只有 2 条**走浮面档位。余下 12 条(tooltip / select
   下拉 / mention 下拉 / SubMenu popper / 表格筛选 / composer 飞出面 / 会话预览卡 /
   prompt 引用卡 / todo 两条 / media 抽屉 / 浮层侧栏)各自 teleport、各自画面,压根
   不是 Popover/Dropdown 家族。**没给它们手工补章**:那枚章的语义是"我的面由浮面
   档位画",而这 12 张面是自己画的,盖上去是一句假话。要收它们,得让它们真的接进
   档位(自绘 UI 收敛的活),接一个,清单少一行。
   验法沿用 Surface v2:两份 CSS 挂进真 Chromium,29 个探针 × 壁纸开/关两态,
   逐条比 computed style(56,696 条)。真实差异 **1 类**,且只出现在合成探针
   `bare-is-surface`(带章但不是 popover 家族的元素)上 —— 真实 DOM 里今天不存在
   这种元素,所以线上逐字节等价;壁纸关闭态 **0 差异**。

2'. **旋钮寻址已落地(批 3b,2026-08-11)。** 用户裁决:「那个面板多少档,这种旋钮,
   应该交由**组件**;至于旋转多少,应该交由**插件**」+「不做宿主手编的旋钮 schema,
   **让插件自己需要什么注入什么 —— token 名字空间本身就是 API**」。

   落法(**不新造 schema**,扩的是 `contributes.theme.overrides` 的校验器):
   - **键按前缀**:`--ot-` 是旋钮名字空间;不以 `--` 起头的键仍走原来那道
     `CSS_VAR_MAP` 判据。两个地址空间在语法上不可能撞车,所以不需要第二个 manifest
     字段、也不需要第二套裁决(共用同一张 winners 表与同一套规范顺序后者胜)。
   - **值按类型**:类型由**后缀**定,`-alpha` → 百分比,`-blur` → px。规则按类型
     写一次,**不按条目维护** —— 组件那边新立一枚同类型旋钮,校验器一个字不改,
     插件当天就能拨。判据表在 `packages/onething-runtime/src/themes/knobs.ts`。
   - **越界钳制、不成形丢弃**:alpha 钳 `[18%, 100%]`(地板取现场 —— 六档里最淡的
     B 级·纱就是 18%,而 B 级面承载正文,那是宿主自己验过的下沿),blur 钳
     `[0, 14px]`(14px 是真机判过"抹成色浆 = 读作没覆盖"的那一档,兼作性能闸)。
     越界仍 `active` 并标 `clampedFrom`;解析不出来的串才丢弃 + 目录页投影可见。

   **落地时挖出的一条真缺陷**(不是设计的一部分,是原来就错了):六枚旋钮里有三枚
   (`card-alpha` / `frost-alpha` / `frost-blur`)声明在 `html.has-wallpaper body` 上。
   主题变量的唯一出口是 `documentElement.style.setProperty`,**行内样式只压得住同一
   个元素上的规则声明** —— 躺在 `body` 的旋钮,根上的覆写够不着。批 3b 把这三枚提到
   根并统一改名进 `--ot-`;`--wallpaper-*` 从此只剩住在 `body` 的派生内部件(ink 快照
   + 兑好的成品色),按名字即可分辨。棘轮:
   `packages/renderer/styles/__tests__/wallpaper-knob-namespace.test.ts`。

   **合流走叠加而不是参数前移**,与颜色相反,判据是同一条的两面:颜色必须前移,因为
   `--ui-*` 语义层、`-rgb`、色阶都**从它派生**;旋钮**没有任何东西从它派生**,主题
   计算里根本不读它。所以它与 `--skin-*` 同构,由宿主
   (`apps/electron/src/main/ipc/themes.ts`)直接叠在下发表上。附带好处:整块能力落在
   干净文件里 —— `applyTheme` 的签名住在 `themes/index.ts`,那份文件当时在未提交名单
   里,碰不得。

   **一条与本文档 §3 纪律二原文相左的实测结论,写在这里免得下一个人再试**:
   "全局行为 = 在根上拨几个 alpha"只对**稀释**成立,对**局部回满**不成立。自定义
   属性的 `var()` 在**定义元素**上解析并按计算值继承 —— token 定义在 `:root`,在
   后代(浮层壳)上改旋钮**不会**让它重算。浮层里要"反馈用满",只能在浮层上把
   token 本身重新声明成墨。于是"稀释作用域的例外清单"是这套机制的**固有成本**,
   不是没收拾干净的尾巴。
2. 既有能力治理文档补纪律三(外观类就绪验收已在壁纸战役承诺,并入)。
3. 今后立项按 §4 决策树走;违例(插件 API 做得了却做成产品硬编码、能力门

## 7. 边界与不做

- 不追求 Eclipse 式"一切皆插件"的全量改造 —— 那是重写,不是纪律。
- 宪法红线不动:枚举能力、宿主执行、永不通用注入。自举改变的是能力
  **从哪里长出来**,不改变能力**以什么形式暴露**。
- 已有产品功能不回头改造成插件;纪律只约束**新**功能与**新**能力门。
