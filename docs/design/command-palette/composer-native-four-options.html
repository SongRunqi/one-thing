命令面板 · 合于 InputBox 四案

四案共用 InputBox 的真实语汇,不再引入第五套视觉:边框 border-strong 52%、 圆角 --radius-xs 4px、零填充、框标签挂在 top:-7px / left:12px 的 mono 9px/ls 2px、 以及 toolbar 那套「全出血单元格 + hairline 30% 分隔 + 整格 hover」。 差别在结构主张,不在配色。每案都连着真 composer 一起看。

案一

连体 —— 面板是 composer 长出来的一节

不是浮在上面的另一个物件:面板与输入框共用同一条边框、贴合无缝,只有最外圈四角是圆的。 框标签从 composer 顶边迁到面板顶边——打开面板时,整个器物换了个名字叫 COMMAND。

主张:命令面板不是弹窗,是输入框的另一种形态。代价是面板与 composer 强绑定, 文件/技能选择器若共用这套壳,它们也都得连体。

案二

分段 —— 把 toolbar 的单元格语法横过来

每一行就是一条 toolbar:类型│命令│说明│⏎ 四格全出血,竖直 hairline 分隔, 列对齐到像素。选中时 kind 格反白(墨底纸字)——这是全app唯一一处实心块, 正因为稀有所以一眼能找到光标在哪。

主张:命令是表格数据,扫列比读行快。代价是描述被压在固定列宽里, 长说明会截断;窄窗口要砍掉描述列。

案四

取景器 —— 一次只看一条,底下一把刻度尺
