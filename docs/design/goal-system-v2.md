# Goal 系统 v2 —— 模型主导的续推(声明制)

2026-07-14。取代 v1 的"计数器盲推"机制。v1 的根本缺陷:续推的决定权在一个
机械计数器手里,系统分不清模型停下的四种含义(干完了 / 需要用户 / 被卡住 /
空转),对所有情况一视同仁地注入合成用户消息"踹一脚"——由此衍生出整条补丁
链(消息折叠、续推刻线、"用户在重复说话"、channel 污染)。

## 原则

**继续是模型的声明,停止是默认;计数器降级为看不见的防呆兜底。**

goal 生命周期的全部决策收敛到一个决策面:goal 工具。系统只做执行和安全阀。

## 模型侧协议(goal 工具)

goal 激活期间,模型每次结束回复前必须调用 goal 工具声明处置,只有三个动作:

| action     | 语义                     | 参数要求                                   |
| ---------- | ------------------------ | ------------------------------------------ |
| `continue` | 继续干                   | `note` 写下一步具体做什么(可选但建议)   |
| `complete` | 目标达成                 | `reason` 必填:交付了什么、证据是什么     |
| `pause`    | 需要用户/无法继续        | `reason` 必填:缺什么、等什么             |
| `get`      | 读状态(随时可用)       | —                                          |

- `continue` 的机制优雅点:**工具调用本身就是循环驱动**——runner 看到
  tool-call 自然进入下一轮,工具结果就是下一轮输入,不需要注入任何合成用户
  消息。
- `complete` 的证据标准从"恐吓式高门槛"改为"声明制":必须说清楚交付物,
  reason 即交付摘要,UI 原地展示。
- `pause` 吸收了 v1 讨论中的 needs_user:带 reason 的暂停已覆盖"等用户"
  语义,不单设状态。恢复仍是用户显式动作(Resume / /goal resume)。
- `blocked` 从模型词汇表移除,降级为系统内部状态(连续错误熔断专用)。

协议的常驻宣告位:`<goal>` turn 变量携带一行协议提示(字节稳定),保证首个
run(goal-set 用户消息本身驱动的那个)也有规则可循。

## 系统侧安全阀(全部静默,UI 不显示计数)

| 安全阀          | 触发                             | 动作                       |
| --------------- | -------------------------------- | -------------------------- |
| 兜底 nudge      | 模型停止但未声明处置             | 注入提醒"请声明";连续失速 N 次(失速检测:有实际工作即重置)才 park |
| max_turns 重驱  | run 被轮次上限截断且 goal 活跃   | 跨 run 全文驱动(保留)    |
| 错误熔断        | 连续失败 3 次(退避重试后)      | status=blocked             |
| 预算            | tokensUsed ≥ budget(默认无上限)| status=budget_limited      |
| 中止            | 用户手动停止                     | status=paused              |

## UI

- GOAL 用户消息(goal-set)与状态栏保留;`complete` 的 reason(交付摘要)
  在 GOAL 消息完成态展示。
- 正常的 continue 就是一次普通工具调用行,无任何特殊 UI。
- 刻线只剩兜底 nudge(标签 `NUDGE`,无数字;罕见出现即异常信号)与
  budget wrap-up 两种。

## 分期

- P1 工具改造(continue/complete/pause)+ 状态机(模型可设 paused,收回
  blocked)+ 模板/turn 变量协议化 —— 本次实施
- P2 complete 交付摘要上 GOAL 消息 UI —— 本次实施(GoalSetMessage 已订阅
  goal 状态,补 reason 展示)
- P3 nudge 去数字化(NUDGE 标签) —— 本次实施
- P4 旧会话兼容:合成消息折叠逻辑保留;'update' 旧动作不再暴露

## 与 v1 保留物的关系

失速检测(madeProgress 重置)、预算/错误/中止熔断、跨 run 重驱、
collapseSupersededGoalDrives 历史折叠、goal-set 消息、路由旁路
(isSystemInternalSource)全部保留——它们是安全阀和地基,v2 只是把
"主机制"从计数器换成了模型声明。
