输入框命令位 · 四案

命令不再画在输入框内部。四个方案都把 /command 抬到输入框之上或边界上, 正文只留参数;四者共用同一底座(图纸边框、mono 图签、分格工具条),差别在于命令"占多大地方、占什么地方"。

共同前提:/cmd 文本仍留在草稿里当唯一事实来源,编辑器把它隐藏,呈现层负责抬起来。 示意场景:已选中 /compact,用户正在补参数。

案一 · 挂签行dock row

与附件行(FILES)完全同构的独立框行,命令是 dock 里的又一条"随草稿走的上下文"。

强
与附件、引用、队列同一套语法,不需要新学;描述文案有地方放;移除目标大。
弱
为一个 token 起一整行,纵向代价最大;同时挂附件时 dock 叠三层显得吵。
适合
命令常带长参数、需要看清它到底是什么的场景。

案二 · 标题块title block

命令直接顶替输入框自己的图签,长在边框线上。不新增任何元素,布局零位移。

强
最省地方,零布局跳动;图签本来就是"这张图是什么"的位置,语义天然吻合。
弱
9px 图签放不下描述;× 只有 13px,点击目标偏小;与语音/音乐争同一个图签位。
适合
命令短、用得熟、不想让草稿区跳动的日常路径。

案三 · 抬头线letterhead

输入框上方一条公文抬头:命令居左、描述跟随、点线牵引到右端的移除。不是"框",只是一条线。

案四 · 接管态mode

不新增元素,而是让整个输入框进入命令态:边框转虚线、图签换成命令名、占位符变成该命令的用法。

强
