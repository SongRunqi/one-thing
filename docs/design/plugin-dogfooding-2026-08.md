# 插件系统第二性原理:自举(dogfooding)

2026-08-11 定稿。起因:壁纸战役(2026-08-10~11)暴露的结构性不安,用户原话:
"我想要做的不是这样的形态 —— 一个插件,功能实现不了,去填补插件系统。"
本文回答这句话:那个循环的根源是什么、为什么它不是插件系统设计错了、
以及用什么建造纪律让它在结构上消亡。

上位文档:插件宪法(redesign §4.2:枚举能力、宿主执行、永不开放通用注入)
**不变**;本文是宪法之下的**建造纪律**,约束的是"能力从哪里长出来"。

## 1. 病理:被讨厌的循环

> 插件想做 X → 系统不支撑 X → 系统大兴土木 → 插件变成薄壳。

循环里插件像个借口:真正的工程全在宿主侧,插件的"意义"只剩触发施工。
壁纸是全程标本:背景能力(G 期)开门时宿主 UI 并没有准备好承接"全局视觉
行为"——109 条自绘 hover、浮面散在消费者手里、区域面各画各的。于是第一个
认真的背景插件装上后,宿主追补了六级体系、四波收敛、G7 三刀、G8 三段。

**诊断:根源不是插件系统,而是一个断层 —— 宿主自身不是用"插件能用的那套
材料"建造的。** 宿主 UI 是历史堆积的手工造物,插件 API 是旁边新开的门,
两者材质不同。插件每想做一件宿主自己没做过的事,就撞进无人区。

## 2. 原理:自举

工业解法只有一个方向(Emacs / Eclipse 是极端形态):**系统自身用插件那套
材料建造**。在这种架构里,"插件想做而系统做不到"这个类别在结构上不存在 ——
系统做任何事走的路,就是插件能走的路;系统给自己造能力时,插件 API 是
**副产品**,不是事后补的门。

onething 不需要(也不该)推倒重来成 Eclipse。需要的是**棘轮式逼近**:
三条建造纪律,让"系统能做的"与"插件能做的"之间的落差单调收窄。

## 3. 三条建造纪律

### 纪律一·自举铁律(功能立项的第一问)

任何新功能立项,先问:**插件 API 做得了吗?**

- **做得了** → 以**内置插件**形态开发(先例:log-monitor、note-skills)。
  功能落地的同时,API 被真实载荷锤炼——每个内置功能都是 API 的常驻测试。
- **做不了** → 说明 API 缺一块**系统自己也需要**的东西 → 先给系统自己造
  这一块(此刻它是系统工程,名正言顺,不是"替插件亡羊补牢"),造完把功能
  以插件形态落上去。
- **系统自己根本不需要这块** → 它就是纯产品功能,**不要硬塞插件形态**。
  (壁纸的正确判法:若当初按此条走,"用户自选壁纸"作为产品设置是更便宜的
  正解;插件形态的价值在"背景"成为多住户能力位之后才兑现。)

### 纪律二·原语自带行为(UI 层的自举 = Surface v2)

宿主 UI 与插件描述树 UI 共用同一批**自带行为的原语**。行为长在组件里:
组件画底的公式是 `color-mix(自己的 ink, 自己档位的 alpha)`,alpha 缺省
100%;壁纸/主题/密度这类全局行为 = 在根上拨几个 alpha/旋钮,**没有**中央
规则本去"覆写-快照-列名"。用了原语的面不是"被规则照顾到",是**天生会**。

推论:wallpaper.css 从 600 行词典萎缩为几十行旋钮 + 开关 + 遗留例外;
ink 快照层、派生 token 列名、两条环坑戒律 —— 这些全是"行为住在组件外"的
代价,行为内置后**连同它们要防的坑一起消失**。

### 纪律三·能力开门前的自举验收

新能力门(外观类、动作类、内容类)开放给外部插件之前,宿主必须已有
**至少一个自己人**跑在同一条 API 上(内置插件或产品功能)。第一个外部
插件不再是探路者。外观类能力另加硬验收:相关表面的原语覆盖率
(`data-surface` / surface-literal 基线数字)达标才开门。

## 4. 决策树(产品 vs 插件 vs 系统)

```
新需求
 ├─ 插件 API 现在做得了?
 │   ├─ 是 → 内置插件形态开发(API 顺带受锤炼)
 │   └─ 否 → 缺的那块系统自己要不要用?
 │        ├─ 要 → 先造系统能力(名正言顺的系统工程)→ 功能以插件落上
 │        └─ 不要 → 纯产品功能,不塞插件形态
 └─ 已是多住户能力位(≥2 个真实住户)?
     └─ 是 → 维持插件形态,宿主成本按能力摊销
```

## 5. 用新透镜复盘壁纸战役

- 背景能力开门时没有过纪律三(宿主 UI 原语覆盖率≈0)→ 第一个外部住户
  变成探路者,循环启动。
- 战役真正的产出不是壁纸,是**迟早要还的 UI 债被提前清偿**:G6 token 族、
  G1-G5 组件能力、G7 章与通用规则、G8 主题层收编、11 条棘轮规则 —— 这些
  全是纪律二的前置件。债不是插件系统造的,是它照出来的。
- far-hills / ink-brand / wallpaper 三个住户共享同一舞台,第 N 个背景插件
  宿主成本为零 —— 摊销开始兑现,决策树"多住户能力位"分支成立。

## 6. 实施排期

1. **Surface v2·行为内置**(纪律二的落地,本文档的第一个实施):原语画底
   公式内置 alpha;wallpaper.css 大幅萎缩;既有六级语义(让位/纱/态/可读卡/
   磨砂/不适用)不变,只换实现宿主。
2. 既有能力治理文档补纪律三(外观类就绪验收已在壁纸战役承诺,并入)。
3. 今后立项按 §4 决策树走;违例(插件 API 做得了却做成产品硬编码、能力门
   没有自己人先行)在设计评审里点名。

## 7. 边界与不做

- 不追求 Eclipse 式"一切皆插件"的全量改造 —— 那是重写,不是纪律。
- 宪法红线不动:枚举能力、宿主执行、永不通用注入。自举改变的是能力
  **从哪里长出来**,不改变能力**以什么形式暴露**。
- 已有产品功能不回头改造成插件;纪律只约束**新**功能与**新**能力门。
