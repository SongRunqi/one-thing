方案 A

频道台 · Rail + Channels

最贴近 Discord 的产品形态对位:空间(rail)→ 频道(群聊房)→ 消息流 → 在场成员。 把 0neThing 的域模型逐个搬到这套骨架上:项目/工作空间 = server、群聊房 = 频道、 同事 agent = 成员、执行会话 = 消息里的活动线(可展开成线程)。 最右的成员栏在这里不是装饰——Discord 的 member list 只能显示"在线/离线",而 agent 的在场是真的有内容的: 谁在忙、在忙什么、跑了多久。视觉仍是纸墨画线风,rail 的选中/未读用左侧墨条而不是彩色填充块。

  • rail = 空间,不是"频道分类"。个人主助理占 rail 第一格(永远第一位同事),项目空间在下面,通讯录钉底。
  • 未读不用红点用墨条:左侧 3px 竖条,8px=有未读,22px=当前空间。彩色红点在纸墨底子上是异物。
  • 署名颜色 = agent 身份色(域模型里的 color 字段),消息本体不带底色;@我 的那条只加一条橙色左墨条。
  • 执行动作压成活动线(虚线 pill):默认一行,点开才是线程。对话面只留"说话",执行细节要主动去看。
  • 成员栏按在场分组:在忙(带活动文案+呼吸环)/ 空闲 / 已注销(灰显墓碑)。这是 presence 四面模型的直接可视化。
  • composer 只有四件:@ / 附件 / speak / 发送。模型、think、context 量尺一律不在此面——那是 agent 的属性。
