F · 块级词汇代码块 / 表格 / 引用块,群聊流里的宽度纪律

markdown blockquote ≠ 回复引用条

blockquote 是灰竖线的内容语义(转述一段话);回复引用条是身份色竖线的会话语义(答的是哪一句)。两根竖线颜色体系刻意分开,永不混淆。

三 · 落地映射每个词汇长在哪个既有扩展点上

  • @提及 pill = markdown-it 行内规则 + 两拍升格:同步渲染中性 span(可进 markdownRenderCache),挂载期按 roster 上身份色、挂点击 —— 与 collabInlineTags 的 <file>/<card> 验真同一套拍子,改名换色不脏缓存。识别只认 message.mentions 里的 id,渲染层不再做名字匹配。
  • 回复引用条改造只动 SayMessageRow 的模板与 CSS:竖线色/小头像来自既有 roster 投影,120 字截断规则(reply-quote.ts)一字不动;跳转落点闪烁复用 is-highlighted。
  • chip 视觉挂在 collab-tag 的升格态上:验真机制零改动,只把 data-collab-resolved 的样式从"链接"升成 chip;未验真态保持哑文本是安全设计,不给样式体面。
  • 代码块折叠是 say 作用域的增量:cb-clamp 只在群聊 scope 生效;语言角标、复制按钮既有链已具备,不重做。
  • 宽度纪律统一 56em:代码块/表格/引用条在 say 里同一个 max-width,聊天列永远读得动;表格自己横滚,不许撑破。
  • 改任何 markdown-it 规则须 bump CACHE_DB_VERSION;新旧转录(纯文本 @名字、无 mentions 字段的老消息)自然落在降级路径 —— 渲染成普通文字,不报错不闪。
  • 悬浮操作条长在 SayMessageRow 模板层,不进 markdown 链:表情 toggle 落到既有 reactions.ts 投影;引用回复装进既有 ComposerReplyBar;absolute 骑行上缘不占行高。「最近使用」表情存本地偏好即可,不进会话数据。
