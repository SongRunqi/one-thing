右侧工作台本来就窄（500px 上下），现在 chrome 吃掉 74px（标签条 34 + 导航条 40）。 本案把两条压成 一条 32px：地址栏常态显示「域名 · 标题」而不是刺眼的裸 URL，聚焦才展开成可编辑的完整地址； 多标签收进地址左侧的计数芯片 ⌄3，点开后下推视口列出标签——因为原生 WebContentsView 永远压在 DOM 之上， 任何"浮在页面上"的下拉都会被它盖掉，只能推、不能浮。加载状态是 chrome 底边一条走线。 取向：单标签为主、把面积让给页面的人。

为什么这样

  • 窄面板里每一行都贵：74px → 32px，视口多出 42px（约多两段正文）。
  • 常态不显示裸 URL——右侧面板的阅读密度已经很高，一长串 query string 是噪声。真要看，⌘L 一秒展开。
  • 标签少于 2 个时计数芯片自动隐藏，chrome 只剩「← → 地址 ⟳ ⊕」。

落地要点

  • 下推层高度变化必须同步 setBrowserBounds，否则原生视图会盖住抽屉。BrowserPanel 的 rAF 对账天然支持，改动只是布局。
  • 域名/标题拆分：new URL(tab.url).host + tab.title，两者都缺时退回全 URL。
  • 进度线用 did-start-loading → 伪进度（0→70% 缓动，加载完冲 100% 淡出），Electron 没有真实进度事件。

代价

  • 多标签是二等公民：切标签要两次点击（开抽屉→选），重度多标签用户会烦。
  • 标签没有常驻可见性，页面标题变化/加载完成不易被察觉——靠抽屉里的状态点补。
