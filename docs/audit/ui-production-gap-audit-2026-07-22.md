# UI 生产级差距诊断报告

日期:2026-07-22
方法:web 端(:5174)真机截图 12 张(聊天主视图/工具轨道/diff/模型选择器/设置页/右栏/Workbench/Memory/Agents/1080px 窄屏)+ 五路独立审查(视觉体系 / 细节打磨 / 竞品对标 / 代码设计系统量化 / UX 信息架构),交叉汇总去重。
截图位于会话 scratchpad(临时目录),报告内以 shot-NN 引用;所有截图可用 Playwright 对 :5174 重新采集。

## 结论

**差距不在审美方向,在三件事:完成度、一致性纪律、信息披露。**

纸墨/账页语言本身成立且有辨识度——右栏点线标签、虚线图纸步骤面板、编号列表、朱砂红强调,这些执行得有味道。"随便下载一个市面 Agent APP 都感觉比我的好"的感受来自:

1. **风格只做了外壳,没做内容**。聊天正文占屏幕 ~70% 面积,而 markdown 表格、代码块、diff、滚动条全是浏览器/库默认的灰色圆角样式,和米色纸面直接打架。外壳再讲究,正文像贴了张别人的截图进来。
2. **微观值不一致是"廉价感"的物理来源**。代码层实测:token 体系纸面完善(878 个变量),但组件侧采用率约 10%——26 种字号、96 种阴影、43 种动效时长、18 种圆角、8 种危险红、23 种 letter-spacing。市面应用不是设计更好,是**重复得更严格**。
3. **驾驶舱全部摊开给用户看**。首屏约 25 个可交互概念(市面产品 6-8 个):composer 一行 9 个控件、右栏五段常驻(多数为空)、guard:danger/ctx/think:max 开发者术语常驻红字。加上死按钮、截断、遮挡,气质从"手账"滑向"内部调试台"。

## A. 生产级底线问题(功能性缺陷,与风格无关,最先修)

### A1. web 端搜索按钮是死按钮 —— HIGH(五路全部命中)
- **证据**:shot-07,点击顶栏搜索图标后界面零变化,无弹层无 toast。
- **为什么致命**:可点击控件点了没反应,用户无法区分"坏了"和"没做",立刻归类为半成品。Electron 专属功能(独立搜索窗)在 web 构建无降级路径的泄漏。
- **修**:platformApi 能力探测——web 端要么隐藏按钮,要么内嵌命令面板式降级,短期至少弹 "搜索仅桌面版可用" 提示。任何一级入口必须有 150ms 内的可见响应。

### A2. composer 浮层遮住最后一条消息,滚到底也看不全 —— HIGH
- **证据**:shot-02 右下角用户消息上缘从 composer 背后露出;shot-09 代码块最后一行压在 COMPOSER 标签下;shot-05 模型弹层最后一行 GLM-5.2 被 composer 截断。
- **修**:消息滚动容器 padding-bottom / scroll-padding-bottom 绑定 composer 实际高度(ResizeObserver 同步,composer 高度随芯片折行变化);弹层 max-height 按 composer 上缘到视口的可用空间计算。

### A3. 文本硬截断遍地,溢出没有策略 —— HIGH
- **证据**:shot-12 芯片 `think:m` 字形被边框拦腰切断(连省略号都没有);shot-05 模型 tab 行 `OPENAI · CODE…` 词中截断;shot-08 变量值 `/Users/yitiansong/dat…` 无 tooltip;shot-01 右栏 `deepseek-v4-pro ·…`。
- **且折叠优先级颠倒**:窄屏时保住了低频的静音/电话/麦克风图标,牺牲了核心的模型芯片(退化成彩色蝴蝶图标)和 think 档位。
- **修**:composer 控件定义显式降级序列(次要图标先进 ⋯ 溢出菜单 → think 缩成图标+tooltip → 最后才动模型名);禁止裸 overflow clip;tab 行横向滚动+两端渐隐;路径值中段省略(保头保尾)+ hover tooltip + 点击复制。

### A4. 悬浮"滚到底"圆钮常态性遮挡内容 —— MEDIUM
- **证据**:shot-01 压在表格数字上、shot-03 压在代码块滚动条上、shot-04 压在 diff 行上、shot-05 压在模型弹层列表上。
- **修**:锚定 composer 上缘(或滚动容器右下角)留固定间隙,弹层打开时隐藏;顺带去投影改纸墨形态(全应用唯一的圆形投影按钮,风格也出戏)。

### A5. 错误信息裸露:"Provider is not supported." —— MEDIUM
- **证据**:采集时右栏 SYSTEM PROMPT 面板内直接渲染此文案(web 端 provider 未接线)。
- **修**:未支持的能力在 UI 层门控(隐藏或给用户话术),内部错误字符串不允许直接渲染。

### A6. 计时回归:步骤显示 `0.0S` —— LOW(但是回归证据)
- **证据**:shot-03 `01 read nlp_test.lua:6826-6835 0.0S`。项目此前有"计时归一 0.1s"的修复(2026-07 工具链路五阶段),这条链路绕过了归一逻辑。
- **修**:耗时钳制下限统一收口;顺带修单位大小写——`3.9S` 是 text-transform:uppercase 波及了单位,时长 token 单独包一层不做变换(3.9s)。

### A7. 窄屏表格 break-all 把电话号码和单词掰断 —— MEDIUM
- **证据**:shot-12 `2363787300` 断成 `236378 / 7300` 两行(数据呈现等于给出错误信息),`Genesys` 断成 `Gene / sys`。
- **修**:单元格禁 break-all,数字/代码 nowrap,表格外包 overflow-x:auto(workspace panels 已有此惯例,聊天内 markdown 表格补齐)。

## B. 风格破功点(纸墨语言执行不到位)

### B1. markdown 表格/代码块/diff 仍是默认灰样式 —— HIGH(视觉路评为"观感差距最大单一来源")
- **证据**:表格是实线全网格+灰填充表头+圆角外框(shot-01/07/12);代码块是灰色圆角卡片+灰条语言标签(shot-02/03);diff 是标准 diff 绿 + 三层容器嵌套(虚线面板套实线卡片套滚动容器,shot-04)。
- **修**:表格账页化(去竖线、表头无填充改小号大写+双细线、行间发丝线);代码块细边线框+右上角字距小标签;diff 新增行改纸系低饱和苔绿(color-mix 6-8%),删中间层实线卡片。

### B2. 滚动条三种样式并存、粗灰默认横条常驻 —— MEDIUM
- **证据**:shot-03 代码块底部 OS 默认粗圆角横条永久可见;shot-04 diff 右缘另一种细深条;shot-10 列表第三种。
- **修**:全局统一 ::-webkit-scrollbar(6px、墨色 20% 透明、hover 加深、overlay 式)。

### B3. ✅ 绿色 emoji 混入正文,一屏最多 5 个 —— HIGH
- **证据**:shot-03/07/09,米/墨/朱砂三色版面上唯一的高饱和色块全是模型输出的系统 emoji,且 `✅这次真的加上去了` 连空格都没有。
- **为什么**:模型的视觉输出不受产品控制,是"内部工具"和"产品"的分水岭。
- **修**:双管齐下——system prompt 加 style 约束(prompts/builder 体系现成);渲染层把 ✅❌⚠️ 映射成墨色 ✓ ✗ 字形并自动补 CJK 间距。

### B4. 彩色蝴蝶 logo 在折叠态冒出来 —— HIGH(并入 A3 的降级问题)
- **修**:provider 图标做单色墨版(currentColor)或字母缩写(DS V4)。

### B5. 设置页整页是另一套 SaaS 语言 —— HIGH
- **证据**:shot-06,近白底、原生 select、灰底 +/- stepper、灰边框按钮、圆角色卡,与主界面只共享一个红下划线段控。
- **为什么**:设置页是用户评估完成度必看的一屏;"精装样板间+毛坯其余房间"。
- **修**:铺回纸面底色;select 换模型选择器同款自绘弹层;分区标题用聊天区的小写大写+发丝线;补齐纸墨表单控件族(下拉/开关/步进器)。

### B6. 按钮体系至少四套并存 —— MEDIUM
- **证据**:裸小写文本按钮(Memory 的 edit/preview/save/reload/open、Agents 的 cancel/save)、灰底填充大按钮(Workbench 的 Files/Terminal/Browser、设置页 Open folder)、红下划线段控、边框芯片、纯图标。Workbench 三颗灰底大按钮是全应用最像默认 Tailwind 的元素。
- **修**:收敛三级——主操作=细线框(+朱砂字);次操作=文本+hover 下划线;工具位=墨线图标。Workbench 三颗按钮改账页编号列表行(01 Files / 02 Terminal / 03 Browser,与 Agents 列表编号语言呼应)。

### B7. 红色一支笔承担四种语义,互相稀释 —— MEDIUM(四路独立命中)
- **证据**:tab 下划线、OUTLINE 当前标记、选中模型、开关、save 按钮(结构强调)/ guard:danger(危险)/ ctx 25% 刻度(进度,且低占用显红是语义反了)/ Memory "● Saved" 红点(报平安用红点,惯例里红点=未保存)。
- **修**:色彩语义表——朱砂红只做"当前/选中"账簿标记;ctx 默认墨色 >75% 琥珀 >90% 红;guard 危险态给全应用唯一的"报警红"形态;Saved 去色点改墨灰小字。

### B8. 阴影语言分裂:硬偏移纸影 vs 软大模糊 SaaS 投影 —— HIGH(代码路)
- **证据**:签名式 `4px 4px 0 color-mix(...)` 硬偏移影被逐字复制 9 份,同库还有 `0 20px 60px rgba(0,0,0,.3)` 类软投影;box-shadow 共 230 处 96 种,仅 35 处走 token。
- **修**:5 档以内海拔 token(--shadow-paper/raised/overlay/modal),全按"纸叠纸"小模糊/硬边重做,软大模糊全库禁用。

## C. 信息架构与披露("像内部调试台"的结构根因)

### C1. 首屏无渐进披露,~25 个概念全摊开 —— HIGH
- **证据**:shot-01——侧栏 3 分组+2 处"显示更多"、tab 栏+agent 下拉+3 无标签图标、右栏 5 段、composer 9 控件、dock 6 图标。市面产品(ChatGPT/Claude/Cursor)首屏 6-8 个。
- **修**:三层披露——常驻(输入框/模型/附件/SEND);会话设置 popover(think/guard/语音三件套);按状态出现(ctx 超阈值才浮现)。composer 常驻控件 9 → 4-5。

### C2. 开发者遥测当一等信息 —— HIGH
- **证据**:guard:danger 红色等宽字常驻每条消息必经之路;ctx 刻度表常驻;右栏 SYSTEM PROMPT/VARIABLES 与 CONTENTS/OUTLINE(阅读辅助)混在一栏;VARIABLES 里 /var/folders 临时目录裸露、空值显示孤立短横。
- **修**:guard 改盾形图标+人话("权限:每次询问/自动放行"),危险态才红;SYSTEM PROMPT/VARIABLES 移入按需打开的 Inspector;术语全部用户化(ctx → hover "上下文已用 25%")。

### C3. 右栏五段同构 label,空态仍占整列 —— HIGH
- **证据**:shot-02 CONTENTS/OUTLINE 后 ~700px 纯空白;shot-12 窄屏下基本全空的右栏仍占 ~256px 固定宽,聊天列被压到 ~510px。
- **修**:空段落不渲染(或折叠成单行 label+计数);全空时整栏收起为边缘开关;<1280px 自动折叠。**空的东西不占地。**

### C4. 三种面板导航模型并存 —— HIGH
- **证据**:Memory/Agents=全屏覆盖(退出靠右上角小写 "close");Settings=独立路由页(侧栏消失);Workbench=侧挂列;模型选择=消息区中央内嵌层(不锚定触发它的芯片)。
- **修**:管理类统一走 Settings 式路由页(Memory/Agents 并入其分组导航);会话伴随类统一侧挂;瞬时选择类统一锚定 popover;退出统一(Esc+固定位置关闭控件)。

### C5. dock 六个无标签图标,一级功能可发现性接近零 —— MEDIUM
- **修**:至少 tooltip+快捷键;更好是展开态给账页风小写大写标签(MEMORY/AGENTS,与现有语言完全兼容)。

### C6. 模型选择器:全宽弹层+双重分组+零信息能力标 —— MEDIUM
- **证据**:shot-05,弹层占满聊天列宽;7 个 provider tab(平均每页 2 条)与列表内分组小节头是同一套词出现两遍;可见 5 行全部带相同的 TOOLS REASONING 标签(零信息,反而淹没了真差异 IMAGE INPUT / 200K)。
- **修**:收窄到 ~380px 锚定芯片上方;删 tab 行留列表内黏性分组头;能力标只显示差异项。

### C7. 会话无自动标题,列表全是手工代号 —— MEDIUM
- **证据**:0810/0720JP/0713/0706需求。自动标题是聊天产品十年来的底线功能。
- **另**:"置顶"是排序属性却建模成文件夹,与内容分组"Music·电台"、兜底分组"未归类"混在同一维度。
- **修**:首轮后 utility model 生成标题(手动改名可覆盖);置顶降为条目属性(别针记号浮顶);"未归类"不显式成组。

### C8. Workbench 空态即菜单,为三选一付出一整列 —— MEDIUM
- **证据**:shot-09,四列布局(侧栏+聊天+右栏+Workbench),新列内容只有三颗灰按钮。
- **修**:入口直接三选一,选中即渲染工具;打开 Workbench 时自动收起右栏——**任何时刻聊天区之外最多一列辅助内容**。

### C9. Memory/Agents 面板是裸 CRUD 台 —— MEDIUM
- **证据**:shot-10 五个小写动词并排无主次("Saved" 状态还混在按钮行里);shot-11 表单占屏 1/4、cancel/save 孤悬右下角距表单 ~600px。
- **修**:内容限宽(~720px)居中;save 提升为主操作紧跟表单尾部;edit/preview 做段控;reload/open/folder 收 ⋯ 菜单。

## D. 排版与节奏(阅读体验的"糙感")

### D1. 消息流垂直留白失控 —— HIGH
- **证据**:turn 间 90-200px 意外空白(疑似空占位块撑高)与 rail 行上下零边距贴死并存(shot-01/02/03/07)。
- **修**:三级垂直间距 token(跨 turn 40-48px / turn 内块间 16px / meta 行 12px),消息渲染只许用这三个值;排查空 steps/thought 占位块撑高度的 bug。

### D2. 用户消息视觉重量过弱,单字"?"塌缩成空方框 —— HIGH
- **证据**:用户气泡=纸底细边框(与输入框、ghost button 同形态),扫读认不出"这是我说的";"?"渲染成 52×62 竖长空框像 UI 残片(shot-03/04)。
- **修**:纸色加深 4-6% 填充 + min-width/padding 统一;或改右缘对齐"登记条目"式(竖细线+小号大写 YOU/时间),归入账页语言。

### D3. 每轮两行元信息:"Thought for Xs" + "思考 N 步 · READ·EDIT·BASH" —— MEDIUM
- **修**:合并一行("思考 23.6s · 3 步 · read·edit·bash")。

### D4. 时间戳 14:51 孤悬、tab 栏下不明灰胶囊 —— LOW
- **修**:时间戳并入消息尾部操作行基线(hover 才现);不明元素给 hover 提示或删除。

### D5. CJK-Latin 混排零间距 —— LOW
- **证据**:侧栏 `IVA需求文档0727`、正文 `到iva`。选了中文衬线+英文等宽这么讲究的组合却没做混排间距。
- **修**:text-autospace(Chromium 已支持)或渲染层 CJK/Latin 边界注入 0.125em。

### D6. 侧栏组头与条目无层级、dock 图标线宽不齐 —— LOW
- **修**:组头改右栏 CONTENTS 同款小号大写字距语言(现成复用);图标统一 icon set 与 stroke。

### D7. 文案语言无统稿:中英混杂、大小写无规则 —— LOW
- **证据**:侧栏中文/右栏英文大写/Memory 英文小写/设置页整页英文/Workbench 英文句子;Agents 的 `templates: developer writer analyst concise ai` 断词歧义(concise ai 是一个还是两个?)。
- **修**:文案宪法——结构标签=英文小型大写;操作与说明=跟随系统语言;并列词一律芯片包裹;一次性统稿。

## E. 代码层量化(设计系统纪律实测)

| 指标 | 实测 | 生产级参考 | 差距 |
|---|---|---|---|
| token 定义 | 878 个(variables.css 1253 行,梯度齐备) | — | 架构本身是好的 |
| token 采用率 | **~10%**(font-size 861 硬编码 vs 105 var;padding 1050 处仅 1 处走 --space) | >90% | **第一根因** |
| 字号种类 | **26 种**,含 ~150 处半像素(11.5/10.5/12.5px),孤例 12.25/8.5/6px | 6-9 种 | 实态众数 12px 比官方梯度低 1-2 档,梯度已失去权威 |
| 阴影 | 230 处 **96 种**;签名纸影被手抄 9 份 | ≤5 档 | 软大模糊混入破坏纸墨语言 |
| 动效时长 | **43 种**;事实标准 0.12s×202 vs token 定义 0.15s | 3 档 | token 记录的不是事实 |
| 圆角 | 509 处 **18 种**;6px 与 7px 并存;最常用值全不在 token 梯度上 | 3 档 | 尖角(账页)与大圆角(iOS 卡片)两种性格混用 |
| 危险红 | **8 个色值**(#b3403a/#ef4444/#dc2626/#e74c3c…,Tailwind+FlatUI 残留混入 Flexoki);fallback 手抄漂移(注入值实为 #dd3333) | 1 | 状态色是全应用最不"纸墨"的地方 |
| letter-spacing | 150 处 **23 种**,px/em 混用 | 1(签名元素) | 签名笔画自己先破功 |
| z-index | 裸写 499/650/900/1000/1200 与 token 梯度(--z-toast 800)混用,1200 压过 tooltip/toast | 全 token | 层叠事故温床 |
| 响应式 | @media 布局断点 14 种;@container 仅 11 处 | 面板级全 @container | 桌面 app 面板宽度由分栏决定,视口断点不触发 |
| 共享样式层 | components.css 仅 437 行 vs 204 个组件(MessageList 2708 行 scoped) | — | 模式靠复制粘贴传播,每抄一次漂移一点 |

**机制结论**:没有共享构件层 → 模式靠抄 → 微观值漂移 → 26 种字号/96 种阴影 → 相邻面板差 0.5-2px → 用户说不出哪里不对但感觉"廉价"。这也是 CLAUDE.md "组件化而不是创建新的组件" 原则在样式层的失守。

## 修复路线(按投入产出比排序)
