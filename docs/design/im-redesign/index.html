Sidebar / 与 Agent 的对话 / 群聊 —— 四个截然不同的方案

四套方案不是四种配色,是四种信息架构:导航模型、消息形态、执行透明度三个轴上各走一个极端。 共用的只有纸墨底子(既有画线风)与域模型(同事 / 房间 / 私聊 / 活 / 在场)。 参考的产品形态分别是 Discord、Telegram、Slack/Linear、以及"无列表的沉浸阅读"。 每套都画了群聊与与 Agent 的私聊两个面,侧栏是各自架构的一部分,不单独出方案。

方案 A

频道台 · Rail + Channels

Discord 的产品形态对位:空间 rail → 频道 → 消息流 → 在场成员栏。四栏,组织感最强,成员栏把 agent 的"在忙什么"直接可视化。

四栏频道心智成员在场栏≥1180px
方案 B

收件箱 · 合流单列表 + 气泡

取消一切分区:群/同事/私下/直聊按时间混成一条列表,靠搜索与 chip 筛选。消息用左右气泡。最轻、最"聊天软件"、零学习成本。

两栏零分区气泡≥860px
方案 C

工作台 · 以活为脊 + 线程常驻

左栏第一区是"进行中的活"而不是对话;中栏账页式高密度消息流,执行动作逐行可见;右栏常驻线程/看板/权限审批。

三栏密度最高透明度最强≥1200px
方案 D

舞台 · 无常驻侧栏 + 在场人物条

侧栏整个拿掉。顶部大头像人物条(谁在、在忙什么、谁在说),中间 690px 阅读列,导航靠 ⌘K 与浮层抽屉。执行细节彻底隐身。

单栏阅读优先⌘K 导航≥900px

共同遵守的几条

  • messenger composer:四套的 dm 房/群房都只有 文本 + @ + 附件 + speak + 发送。模型/think/context 量尺一律不进对话面——它们是 agent 的属性(agent-im-chat-ui.md C2)。
  • "说的话"与"干的活"分层:消息体只承载 say 的内容,执行动作一律降级为可展开的旁支。四套的区别只是这条旁支露多少(C 最多 → D 最少)。
  • 墓碑不消失:retired 同事在任何面里都灰显保留,历史署名与履历可读(agent-domain-model.md M3)。
  • 身份色来自域模型的 color 字段,只用在署名与头像,消息本体永不带底色——纸墨底子上大面积彩色即失控。
  • 点头像 = 进 Agent 空间页(资料/会话/文件/搜索),四套只是落位不同:A 右栏、B 抽屉、C 右栏 tab、D 全屏。

落地时的复用面(不在本文实施)

  • 四套都不新写第二个输入框:沿用 InputBox 的 composerProfile 形态分装(engineering / messenger)。
  • 侧栏三段(联系人/群聊/私下)的数据源已在 Sidebar.vue + sessions store 里现成;A/C 是重排,B 是合流成一个 selector,D 是把同一份数据搬进浮层。
  • 在场数据 = listAgentPresence(app/agents/presence.ts)已落地,A 的成员栏、C 的卡片状态、D 的人物条吃的是同一份。
  • C 的活动线/线程吃的是 StepsPanel 与 diff-hunks 既有结构;右栏走 RightWorkbenchPanel 多实例基建。
