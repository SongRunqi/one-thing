## 0. 这份清单怎么用

D8 的验收标准不是「功能跑通了」，而是蓝图 §0 那**四个必答问题**：用户在任何时刻能不能回答

1. **这间房现在怎么了？**（§2，OB1–OB5）
2. **这个人现在在干嘛？**（§3，OB6–OB8）
3. **整个系统在忙什么？**（§4，OB9–OB10）
4. **刚才为什么是那样？**（§5，OB11–OB14）

每条 = **造出场景 → 在哪看 → 预期看到什么**。看不到 = 这一问没答上，缺一即不合格。

> ### ⚠️ 诊断 CLI 必须用 `bun` 跑
>
> ```bash
> bun scripts/collab-v3-inspect.mjs            # 对
> node scripts/collab-v3-inspect.mjs           # 错 —— 第一个 import 就炸
> ```
>
> 它直接 import TS 源码并走 tsconfig 的 `@onething/*` 路径别名，裸 `node` 解析不了别名。
> 与 `collab-v3-migrate.mjs` / `collab-v3-replay.mjs` 是同一条规矩。

### 0.1 CLI 是**只读**的，跑它不用停 server

`collab-v3-inspect.mjs` 只 `readFileSync`：不写任何文件、不改 `~/.onething`、不起 server、不碰 store lock。
房账走的是同步原子写（`writeFileSync` + `renameSync`），所以**边跑边看**读到的永远是某一版完整的账，不会是半份。

这与走查的另一条纪律不冲突但要分清：**用编辑器改 `~/.onething` 下的文件之前仍然要先停 server**（两个进程同时写，后写的赢）。只读不用停，要写就停。

### 0.2 进程外读不到的两样，CLI 一律**如实标注**

| 读不到的 | 为什么 | CLI 怎么说 | 要看真值去哪 |
| --- | --- | --- | --- |
| **「生成中」** | 判据是 turn-context 登记簿，内存态 | 只报 `持牌 N`，附「执行态需进程内，见 UI」 | 状态条的 `持牌 N · 生成中 M` |
| **预算闸** | 用量账本不在房账里 | 重算的 `blockedBy` 缺这一格 + 一条 `!` caveat | 时间轴的 `gate-block` 行（进程内的原话） |

看到这两条 `!` 提示不是 bug，是**设计**。反过来说：**如果哪天 CLI 不打这两条了，那才是 bug**（有人把「猜」当成了「知道」）。

## 1. 前置与约定

### 1.1 环境

```bash
bun run build       # UI 走查前必须重 build —— dev 与 build 产物在 scoped CSS 上表现不同
bun run dev         # 或分泳道:dev:electron / dev:web
```

### 1.2 需要预备的场景

| 代号 | 场景 | 用在哪几条 |
| --- | --- | --- |
| R3 | 一间 ≥3 人的群房（含 PM），预算与闸可改 | OB1 OB2 OB4 OB9 OB11 OB14 |
| R2 | 一间 2 人群房（好造「一人在别处说话」） | OB3 OB6 |
| RD | 一间用户↔agent 私聊房 | OB3（别处那一间） |
| RW | 一张 board 卡（能派出 work 子 actor） | OB7 OB9 |
| RK | 一间刚说过话、可以被 `kill -9` 的房 | OB12 |

### 1.3 三个常用命令，先记住

```bash
bun scripts/collab-v3-inspect.mjs                        # 系统总览:所有房 + 所有同事各一行
bun scripts/collab-v3-inspect.mjs --room <id|名字>       # 单房:账 + 租约 + 举手 + 裁决 + 时间轴尾 20
bun scripts/collab-v3-inspect.mjs --agent <id|名字>      # 单人:大脑 / 邮箱 / 持牌 / 工作卡 / 涉入房
```

补充档：`--tail <n> [--type a,b] [--room id]`（时间轴回放）、`--dead-letters`（全仓死信）、
`--json`（任一模式的机器可读版）、`--store <path>`（对一份副本跑）。

`--room` / `--agent` 后面**可以直接写名字**：先精确 id，再精确名字，最后子串。
命中多个时它**不猜**，把候选列出来让你再说一次——诊断工具认错目标的代价是「你看的是另一间房的账」，那种错在屏幕上完全看不出来。

## 2. Q1：这间房现在怎么了？

### OB1 · 裁决窗三态：防抖 → 在飞 → 降级

**操作**
1. 在 R3 里发一条**不 @ 任何人**的普通问题（例：「大家觉得这个方案的风险在哪」）；
2. 全程盯 `CoordinatorStatusBar`（房间顶部状态条）；
3. 想看降级态：把裁决模型的 key 改错 / 断网重发一条，让裁决超时（`COLLAB_REFEREE_TIMEOUT_MS = 8000`）。

**在哪看** 状态条的裁决那一格（`packages/renderer/components/workbench/CoordinatorStatusBar.vue`）。

**预期** 三个**长得不一样**的样子依次出现：

1. **防抖**（150ms，虚点）——窗刚开、裁判还没被买；
2. **在飞**（转圈 + 候选头像）——裁判调用在路上；
3. **降级**（黄牌「裁决降级：FIFO」）——超时/端口崩/解析失败/无裁判时亮起。

第 3 态是这一期必须修的一处链断：降级在旧口径里与「没有裁决在跑」长得一模一样（`judging: 0`）。

**CLI 佐证** `--room <房> ` 的「裁决窗」段。注意**口径差**：账上只有 `pending / resolved / degraded` 三态，
**150ms 防抖窗只有进程内看得到**，所以 CLI 在防抖期一律显示「在飞」。降级则在时间轴上留了一条
`judge-degraded` 行，CLI 会把它印成「! 最近降级 … 原因=…」。

**失败时看哪儿** `room-actor.ts` 的 `buildCollabRoomActorJudgmentView`（三态映射）+ `runtime.ts` 的 `roomSnapshotOf`（防抖那一格由它补）。

---

### OB2 · 排队徽标细分成六格，hover 出明细

**操作**
1. R3 里把 `maxConcurrentTurns` 调成 1，发一条会让三四个人都想说的话；
2. 等第一个人拿到牌开始说，其余的人排队；
3. hover 状态条上那个「排队」徽标。

**在哪看** 状态条的排队徽标 + hover 明细行。

**预期**
1. 徽标不再是笼统的「N 人排队中」，而是分档显示：`裁决中` / `等座位` / `链闸` / `相位挂起` / `冻结` / `预算`；
2. hover 出的明细行里，每个人后面跟着**它卡在哪道闸**；
3. 这一批人的判据**是同一个**（闸是房间级的，不是按人开的）——如果两个人显示不同的闸，那是 bug。

**CLI 佐证**
```bash
bun scripts/collab-v3-inspect.mjs --room <房>
```
「举手」段每行末尾就是 `卡在 等座位`。若时间轴上进程内记的闸与重算的不一样，CLI 会并排印出来：
`卡在 裁决中(账上记的是 等座位)`——**两个都给**，因为进程外那次重算缺预算闸那一格（§0.2）。

**失败时看哪儿** `room-rules.ts` 的 `resolveCollabRoomHandBlock`（六道闸的次序）+ `coordinator-status.ts`（徽标分档）。

---

### OB3 · 「持牌」与「生成中」分离 —— v3 特有的那个中间态

**操作**（这条要**刻意造**，不会自己撞见）
1. 在 RD（私聊房）里给某位同事发一条会让它想很久的消息，让它的大脑忙起来；
2. **趁它还在私聊里生成**，切到 R2（那位同事也在的群房），`@` 它一句；
3. 立刻看 R2 的状态条与成员条。

**在哪看** 状态条的 `持牌 N · 生成中 M` 两个数字 + 被 @ 那位的名字后缀。

**预期**
1. R2 里 `持牌 1 · 生成中 0`——它拿到了牌，但大脑还在别处；
2. 那位的名字后面带「（在别处思考）」；
3. 私聊那一侧结束之后，M 才涨到 1，后缀消失。

这就是蓝图 §1 那张词汇表要修的东西：v3 之前这两种状态在界面上都叫「发言中」。

**CLI 佐证** CLI **看不到**第 2 步与第 3 步的区别（登记簿是内存态），它两次都报 `持牌 1`，
并附「执行态需进程内，见 UI」。**这正是预期行为**——CLI 说的每一句都要是它真知道的。

**失败时看哪儿** `turn-context.ts`（登记簿）+ `room-actor.ts` 的 `executingLeaseIds` 供数 + 状态条的 M 计数。

---

### OB4 · 链闸顶格：挂起原因写在脸上

**操作**
1. R3 的 `budgets.maxChain` 调小到 3；
2. 不插话，让同事们自己连着说到顶（或直接发一条会引起接龙的话）；
3. 看状态条的链闸读数与排队徽标。

**在哪看** 状态条的三闸读数 + 排队徽标 + 右栏的「调度」页签。

**预期**
1. 链闸读数走到 `3/3`；
2. 之后还举手的人，徽标是 `链闸`（不是笼统的「排队中」）；
3. 房间里最多贴**一行**撞闸系统行（同一次只说一遍的闩锁），不刷屏；
4. 人类插一句话之后链清零，读数回 `0/3`，挂起的手放行。

**CLI 佐证**
```bash
bun scripts/collab-v3-inspect.mjs --room <房>                         # 「闸」那行:链 3/3
bun scripts/collab-v3-inspect.mjs --tail 30 --type gate-block --room <房>
```
第二条命令直接给出「谁在什么时刻撞了哪道闸」——**V19 那条「要记数」的条目，现在数得出来了**。

**失败时看哪儿** `room-rules.ts` 的链闸分档（`chainCount` 计在发牌那一刻，不是说话那一刻）+ `notices.chain` 闩锁。

---

### OB5 · 冻结与相位挂起

**操作**
1. 冻结 R3（房间设置里的总闸），发一条消息；
2. 抬闸，再发一条。

**预期**
1. 冻结期间举手的人徽标是 `冻结`，房间最多贴一行冻结提示；
2. 抬闸之后照常走裁决 → 授牌 → 发言。

**CLI 佐证** `--room <房>` 的房头那行带 `**冻结**`，举手段的判据是 `卡在 冻结`。

> **相位挂起**（`phase`）在 D7 走查里记的是「策略没接线」（V13）。这一期只保证**它一旦发生就看得见**：
> 房头会印 `相位=<名>`，判据会是 `卡在 相位挂起`。相位本身能不能被设置，仍按 V13 的结论走。

## 3. Q2：这个人现在在干嘛？

### OB6 · 成员条四态徽标

**操作** 在 R2/R3 里制造三种状态：一位在说话、一位持牌但大脑在别处（复用 OB3 的造法）、一位有 running 工作卡（RW）。

**在哪看** `packages/renderer/components/chat/RoomMemberStrip.vue` 的头像徽标。

**预期** 四态各一个样子：🟢 生成中 / 🟡 持牌等大脑 / 🔵 干活中 / 无徽标 = 空闲。
关键是**徽标从 agent 快照派生**，不再是「从看板 doing 卡现算在忙」——同一个人在成员条、状态条、Agent 空间里说的是同一件事。

**失败时看哪儿** `collabBoard` store 的 `agents` 那本账（seq 去序 + 冷启动 GET 补水 + TTL 陈旧兜底）。

### OB7 · Agent 空间的「大脑」面板

**操作**
1. 打开某位同事的 Agent 空间（`packages/renderer/components/agents/AgentSpace.vue`）→「大脑」tab；
2. 让它同时：在一间房里说话、在另一间房里持牌、跑一张 RW 工作卡；
3. 在它忙的时候往它所在的另一间房发消息（制造邮箱积压，见 V12）。

**预期** 六格全有：
1. 大脑状态大字：`正在「房名」思考（时长）` / `等待中（持 N 张牌）` / `空闲`；
2. 持牌清单：房名 + 时长 + 是否执行中；
3. 邮箱：积压深度 + 最旧事件时间 + 最近 5 条**事件类型**（保密纪律：**不带正文**）；
4. 工作卡：running / done / interrupted 各卡状态与时长；
5. notebook 尾部窗；
6. 死信计数（常态 0）。

**CLI 对账**
```bash
bun scripts/collab-v3-inspect.mjs --agent <名字>
```
逐格对：`持牌` 条数、`信箱 积压/最旧`、`工作卡` 状态、`涉入房` 轮次。
**邮箱深度两边必须一致**——UI 走的是进程内游标差，CLI 走的是 `inbox.jsonl` 与 `inbox.cursor` 的差；
对不上说明有一侧的游标没落盘（那正是「重启后重复发言」的前兆）。

**失败时看哪儿** `app/collab/agent-activity.ts`（九格的组装）+ `agents-v3/<id>/inbox.cursor`。

### OB8 · 一个人牵涉的房，一次看全

**操作** 挑一位在三间以上房里活动过的同事，跑 `--agent`。

**预期**
1. 「持牌」列的是**各房账**里那几张牌（房间是租约的权威），而不是 agent 账上那份可能过期的备份；
2. 「涉入房」按最近开口排序，带轮次；
3. 名字能直接用（`--agent Iris`），不用抄 uuid。

**失败时看哪儿** 若某间房里明明持着牌但 CLI 没列出来，先看那间房的 `actors/room.json` 是否落盘（账必须跑在转录前面）。

## 4. Q3：整个系统在忙什么？

### OB9 · 调度总览页

**操作** 让两三间房同时有人在说话 + 至少一张 running 工作卡，打开 workbench 的「调度总览」页。

**预期**
1. 顶部三数字：在飞 LLM 调用总数（对话 / 裁决 / 工作三色）、全局工作槽 4 的占用、死信总数；
2. 上半：活跃房卡片流（每房一行：持牌 / 举手 / 裁决态 / 三闸迷你条）；
3. 下半：agent 矩阵（每人一行：大脑状态 / 持牌数 / 邮箱深度 / 工作卡数 / 死信）；
4. 关掉窗口再开，数字**立刻回来**（冷启动 GET 补水，不是等下一次事件）。

### OB10 · CLI 总览与 UI 总览对账

**操作**
```bash
bun scripts/collab-v3-inspect.mjs
```

**预期**
1. 房清单里，**有人持牌的排在最前**，其次是有人举手的；
2. 每间房那行的 `持牌 N/座位上限`、`举手 N(闸)`、`链 N/上限`、`策略` 与 UI 上那一行对得上；
3. 同事清单里的 `持牌 / 信箱 / 工作卡 / 上次开口` 与 Agent 空间对得上；
4. 头三行里有一行写着「「持牌」≠「生成中」——执行态需进程内，见 UI」；
5. 尾部有那条预算闸 caveat。

**机器可读版**
```bash
bun scripts/collab-v3-inspect.mjs --json | jq '.totals'
```
`{rooms, agents, leases, hands, deadLetters, inboxBacklog}` 六个数——这是未来自动化盯盘的那一格。

**损坏文件的行为** 手动把某间房的 `actors/room.json` 改成半截 JSON（**先停 server**），再跑一次：
预期是**那一项报 `!` 一行、别的房照常输出**，不是整条命令炸掉。看完记得还原。

## 5. Q4：刚才为什么是那样？

### OB11 · 时间轴回放：一条消息之后发生的全部事，串成一条链

**操作**
1. 在 R3 里发一条不 @ 人的问题，等一轮跑完；
2. 打开右栏的「调度」页签 → 时间轴视图；
3. 同时跑 CLI 对照：
```bash
bun scripts/collab-v3-inspect.mjs --room <房>          # 尾 20 条
bun scripts/collab-v3-inspect.mjs --tail 40 --room <房>
```

**预期** 一条完整的因果链，按类型着色 / 每行末尾带 `← 因果引用`：

```
posted(msg-9) → hand(A, ←msg-9) → hand(B, ←msg-9) → judge-open(候选 A,B ←msg-9)
→ judge-verdict(排序 A, why=…, 耗时, 模型 ←msg-9) → grant(A, lease-1 ←msg-9)
→ gate-block(B, 等座位 ←msg-9) → speak(A, msg-10 ←lease-1) → yield(lease-1)
```

1. 每一行都指得回上一件事（`triggeredBy`），不是一堆时间上挨着、逻辑上互不相干的行；
2. **一个字的消息正文都没有**——只有 id 引用与枚举（保密纪律，蓝图 §7）；
3. 账本落在 `~/.onething/collab/<roomId>/actors/scheduler-log-<日期>.jsonl`，按日切、保留 14 天。

**失败时看哪儿** 写入点收敛在房账转换处（`deriveCollabSchedulerLogRows`）与 AgentActor 死信处；
少了某一类行，先看那一处有没有接上 sink。

---

### OB12 · `kill -9` 之后用 CLI 验尸

**操作**
1. 在 RK 里让一两位同事说着话（有牌在外、有手在队里）；
2. **`kill -9`**（不是正常退出）：
```bash
pgrep -fl "onething|Electron" | head        # 找到主进程 pid
kill -9 <pid>
```
3. **不重启 app**，直接跑 CLI：
```bash
bun scripts/collab-v3-inspect.mjs --room <房>
bun scripts/collab-v3-inspect.mjs --tail 40 --room <房>
```

**预期**
1. CLI **跑得起来**（这就是「app 挂了也能查」那句承诺——抓瞎最惨的时刻恰恰是进程不对劲的时刻）；
2. 房账完好：租约表、举手队列、链读数、水位都在，不是半份（同步原子写的效果）；
3. 时间轴完好到**倒数几行**：它是普通追加、不每行 fsync，掉最后一两行是**设计上可接受的**（诊断不是账）；
4. 重启 app 之后，V23 那条「不冻死、不重播」照旧成立，且时间轴上能看见换代（`phase` / 新 `grant` 的 epoch 变化）。

**这条同时验的是** V17（卡级停止跨重启认账）与 V23（租约/广播跨重启）——现在它们有了盘上的证据，不用再靠界面推断。

### OB13 · 死信：从「静默变哑」到「看得见」

**背景** 死信在 D8 之前是一个**没有消费者**的内存环：一封信炸了，循环继续跑（那是对的），而系统静默变哑。
用户看到的是「它没回应」，真相是「它试过但炸了」——两者在界面上完全无法区分。

**操作**
```bash
bun scripts/collab-v3-inspect.mjs --dead-letters
```

**预期（常态）**
```
死信 0 —— 全仓账本上没有一条事件处理失败(常绿即健康)。
```
状态条尾部**没有**红点，Agent 空间的死信计数是 0。

> **不提供人造死信的配方。** 死信是「事件处理抛异常」，没有已知的用户可触发路径——真有一条，那本身就是要修的 bug。
> 所以这一条的验收判据是**常绿即健康**：`--dead-letters` 长期为 0，且**一旦不为 0 就要能看见**（下面这三路）。

**真出现时，三路出口都要在**：
1. **计数**——状态条尾部红点 + Agent 空间死信计数（读的是 ActorBase 环长，不另立一本账）；
2. **详情**——时间轴上一条 `dead-letter` 行，带 actor / 事件类型 / 错误首行；CLI 的 `--dead-letters` 按 actor 分组汇总；
3. **告警**——`console.warn` **一次**（每 actor × 每类事件的首错闩锁，不刷屏）。

点红点应跳到时间轴并过滤到 `dead-letter`；CLI 那侧等价命令：
```bash
bun scripts/collab-v3-inspect.mjs --tail 50 --type dead-letter
```

**如果要在开发机上验证这条链**（可选，**不要在真数据上做**）：用 `--store` 指一份副本，
手工往 `collab/<id>/actors/scheduler-log-<今天>.jsonl` 追加一行 `{"type":"dead-letter","at":…,"actor":"agent:x","eventType":"room:posted","error":"…"}`，
跑 `--dead-letters` 看分组是否成立。这只验**读**那一侧；写那一侧由 `createCollabDeadLetterSink` 的单测盯着。

### OB14 · 裁决回放：「刚才为什么没人理我」从猜变成查

**操作**
1. R3 里发一条不 @ 人、大家都不太想接的话（例：「好的」）；
2. 没人说话之后，打开「调度」页的裁决卡片；
3. 或直接：
```bash
bun scripts/collab-v3-inspect.mjs --tail 20 --type judge-open,judge-verdict,judge-degraded --room <房>
```

**预期**
1. 看得到**最近一次裁决的完整回放**：候选是谁、排序是什么、`why` 一句话理由、耗时、用的哪个模型；
2. 「谁都不该说」是一个**有效答案**（`order` 为空），界面/CLI 要把它印成「排序=(无人)」而不是当成失败；
3. `judge-open` 的**条数**是「买了几次裁决」——V7 那条「一窗一调用」现在不用去翻 provider dump 就能数；
4. 降级过的那次带 `judge-degraded` 行与原因（timeout / 解析失败 / 无裁判）。

**这一格的长期价值**：换裁决算法时有对照数据。qm 的文档当年就指出——没有账本就无法对比算法。
